## 2. 环境准备

### 2.1 只用命令行

```bash
pip install -r requirements.txt        # numpy + matplotlib
```

核心算法**只需要这两个包**。

### 2.2 还要用网页界面

```bash
python3 -m venv --system-site-packages .venv   # 复用系统已装的 numpy/matplotlib
.venv/bin/pip install -r requirements-web.txt  # nicegui + plotly
```

`requirements-web.txt` 与 `requirements.txt` 分开，是为了让只用命令行的人不必装 UI 依赖。

### 2.3 自检

```bash
PYTHONPATH=python .venv/bin/python -m pytest python -q
```

看到 `NNN passed` 即可。系统 python（无 nicegui）也能跑核心测试：
`PYTHONPATH=python python3 -m pytest python/excitation_trajectory python/robot_model -q`。

## 3. 网页界面

### 3.1 启动与停止（入口 `laser_web.__main__`）

```bash
cd ~/projects/robot-calibration-playground

# 前台（调试用，报错立刻可见）
PYTHONPATH=python .venv/bin/python -m laser_web --port=8765

# 后台常驻（关掉终端也不停）
nohup env PYTHONPATH=python .venv/bin/python -m laser_web --port=8765 \
  >/tmp/laser_web.log 2>&1 &
```

浏览器打开 **http://127.0.0.1:8765**。

停止：

```bash
kill $(ss -ltnp | grep ':8765' | grep -oP 'pid=\K[0-9]+' | head -1)
```

要点：

| 项 | 说明 |
| --- | --- |
| 地址 | **只监听 127.0.0.1**，别的机器访问不到（无鉴权，有意如此）；`--host 0.0.0.0` 会被拒绝 |
| 端口 | 默认 8765；被占用就换，如 `--port=8790` |
| 必须 `.venv/bin/python` | 系统 python 没装 nicegui |
| 必须 `PYTHONPATH=python` | 否则 import 不到 `excitation_trajectory` / `robot_model` |
| 参数写法 | 用 `--port=8765`（等号），避免终端折行把参数拆成两条命令 |
| 产物 | `runs/<时间戳-随机>/`，保留最近 50 次；已 gitignore |

### 3.2 生成页（`生成`，`pages/generate.py`）

用于生成 N 个标定路点。

- **机器人模型**：只列 `Nexbot6R` 真能加载的文件（目前两个 URDF）。`*_dh.json`、`*_scan.json`、
  `robot_sim/*.json` 会被折叠到"另有 N 个文件不能当模型用"里并给出原因。
- **采样域**：两种输入方式二选一
  - 两点式：给可达区域的最小点与最大点；
  - 六数式：`X 下界 X 上界 Y 下界 Y 上界 Z 下界 Z 上界`。
- **网格**：两种方式二选一
  - 目标点数（默认 50）：程序自动选一组份数恰好凑满，优先纯网格、其次各轴格距最均匀；
  - 手填格点数：界面按**格点数（= 份数 + 1，方便直接估点数）**输入，提交前换算回份数。
    总点数 = `X×Y×Z 格点 + Z 层间插点`。
- **参考姿态**：`A/B/C`（度）+ 欧拉约定（只有内旋三种，见 [7.2](#72-欧拉约定只保留内旋)）。
- **姿态扰动半宽**：三轴各多少度；`seed` 决定随机序列，同参数重跑逐字节可复现。
- **守卫**：`|J5| 下限`、`|J3| 下限`、`段内下限`、`条件数上限`、`段模型`（`MOVL` / `PTP`）、
  `段采样`、`q-seed`。
- **预览卡片**：**改任何参数都会实时刷新**三边长度（米）、网格、点数、设计条件数（不跑 IK）。体积仍由 `core.preview_domain` 返回（`volume_m3`），只用于修复页算"采样域缩小"，不再占预览卡一行。
  点数超过 5000 会标红并禁用按钮——防止手滑填出几百份数把内存吃穿。
- **两个按钮**：
  - `预览路点`：只生成路点与 3D 图，不算 IK；
  - `生成并解算`：完整跑一遍，进度条 + 实时日志 + 可取消。
- **结果区**：统计卡（成功数 / 构型切换 / ΣdqL2 / `|J5|min` / `|J3|min` / 条件数 / 是否可行）、
  可旋转 3D 图、可排序路点表（失败行标红）、段诊断表、导出 `scan.json` / `joints.txt` / `plot.png`。

### 3.3 奇异修复页（`奇异修复`，`pages/repair.py`）

现场跑点时报奇异，用这一页重新规划。

1. **现场信息**：填「已走到第几点」和控制器停下来的 6 个关节角（可加多组按 `+`）。
2. **采样域 / 姿态**：与生成页相同的字段。
3. **修复策略**：是否允许改参考姿态、是否允许收缩、`经验裕度`、`位置禁区半径`。
4. 点 `定位段`：列出该点前后各段的 MOVL 剖面（段内 `|J3|/|J5|` 最小、是否穿零、最差点坐标）。
5. 点 `修复`：先尝试**只换该段端点姿态**（位置/网格不动），不行再做整体搜索（平移/收缩/改姿态）。

结果区给出判定徽标（`退化读数` / `腕奇异` / `肘奇异` / `模型解释不了`）、修复前后对比、候选日志，
以及修复后计划的统计卡 / 3D 图 / 路点表。

### 3.4 ISO 五点页（`ISO 五点`，`pages/iso9283.py`）

生成 ISO 9283 定位精度测试的 P1～P5，**只出笛卡尔坐标**。

- **立方体**：**只有一种给法**——`给最大/最小点`（`cube_mode="bounds"`）：填两个极值点；
  取中点为心、**最小跨度**为边长（三轴不等长会提示）。页面上没有自动搜索、也没有
  “布点 / 截面”选项（ISO 9283 只定义了一种取法），边长的搜索与三种布点只留在命令行
  （见 [4.3](#43-excitation_trajectoryiso9283_cube--iso-9283-p1p5) / [7.3](#73-iso-9283-五点布点)）。
- **布点 / 截面**：固定 `vertices` / `xz`（XZ 对角截面的四个角）。界面上不可选，
  但 `collect()` / `form_to_params()` **仍然提交**这两个键——`core` 的参数约定不变，
  `meta.layout` / `meta.plane` 照旧落盘。
- **五点编号（ISO 9283）**：P1 = 立方体中心；**P2 / P3 在小 X 小 Z 一侧，P4 / P5 在大 X
  大 Z 一侧**（同侧两点只差 Y）。这是 `cube_points` 的编号，界面预览表与结果表都按它标注。
- **只算坐标，不显示关节量**：页面走 `core.iso_points`（不是 `run_iso9283`），返回
  `{"points": [{"name", "pos", "reachable"}], "summary": {"reachable", "total"}, "meta"}`。
  IK 每点只解**一次**、固定种子（`core.ISO_REACHABILITY_SEED`），结果只体现为
  `reachable`；界面上**没有** `q1..q6`、`|J3|` / `|J5|`、构型标签，也没有 `q_seed` /
  `j5_min` 输入（`core` 用自己的默认值）。
- **姿态**：五点都用用户填的参考姿态，**不加扰动**（ISO 页没有 ±A/±B/±C 控件），现场按 MOVL 依次走。
- **没有后台任务**：几何是微秒级、5 次 IK 是毫秒级，`start_iso()` 在主线程算完
  （实测约 10 ms），所以没有进度条 / 取消 / 日志面板。产物（`iso.json` + `iso.png`）
  **在点导出时才生成**（`core.save_iso_points`，matplotlib 出图约 0.3 s）。
- 结果：`可达 N/5` + 边长 + 中心、3D 图（绿圆 = 可达、红叉 = 不可达，悬停只有 XYZ）、
  五点表（P / X / Y / Z / 可达）、导出 `iso.json`（每点 X/Y/Z + 参考姿态，
  **没有关节角**）/ `iso.png`。

> `iso.json` 不含 `q`，所以 ISO 的运行**不能**在「工具」页导 GP；要导 GP 用「生成」页的
> `scan.json`。`core.run_iso9283`（带 `q`、与 CLI 的 `iso.json` 同构）保留给命令行与
> 一致性检查，界面已经不再走它。

> 服务层 `core.run_iso9283` 还保留 `cube_mode="center"`（中心 + 边长）与 `"points"`
> （`params["points"]` = 5×3 坐标，不依立方体）：**只有测试在用**，界面不暴露、
> CLI 也没有 `points` 的对应参数。保留它是为了将来"外部给一组现成坐标"的场景，
> 别误当成界面能力。`"auto"`（自动搜内接立方体）同样只剩命令行。

### 3.5 工具页（`工具`，`pages/tools.py`）

- **GP 导出**：选一次运行 → 上传 `position_R1_template.json` → 设 `起始 GP 号` / `标志位` /
  `笛卡尔` / `单位` / `欧拉` → 生成并下载。模板**只读**，`controllerID` 与版本号原样保留。
- **JSON → URDF**：上传控制器 JSON + 填型号 → 下载 `<原文件名>_<型号>.urdf`，页面显示自校验误差。
- **运行目录**：列出 `runs/` 里的记录，可一键清理（保留最近 50 次）。

## 3.5 桌面版（laser_desktop.__main__）

交付形态是 **Windows 安装包**（不是网页）。四页（生成 / 奇异修复 / ISO 五点 / 工具）与
网页版共用同一份 `laser_web.core`，差别只在**参数从哪来**：网页是 NiceGUI 控件的值，
桌面是 Qt 控件的值（`GeneratePage.values()` → `form_to_params()`）。

```bash
# Windows（交付形态；QtWebEngine 在 PySide6-Addons 里）
pip install -r requirements-desktop.txt
PYTHONPATH=python python -m laser_desktop

# Linux（本机验证；PySide6 的 Linux wheel 不含 QtWebEngine，退回系统 PyQt5）
sudo apt install python3-pyqt5.qtwebengine
PYTHONPATH=python python -m laser_desktop

# 只打印路径解析 + 许可证状态（排查"打包后找不到模型"）
PYTHONPATH=python python -m laser_desktop --print-paths
```

### 3.5.1 分层

| 模块 | 管什么 | 改它之前必须知道 |
| --- | --- | --- |
| `paths` | 只读资产根（模型、随包 JS）与可写数据根（`runs/`、缓存） | **`sys.frozen` 的坑**：仓库里其它模块用 `Path(__file__).parents[2]` 反推仓库根，冻结后 `__file__` 落在 `_internal/` 里，推出来是个不存在的路径（模型找不到、`runs/` 建不出来）。所以桌面版一律走 `paths`：`asset_root()` 转调 `laser_web.paths.asset_root()`（只定义一次），`data_root()` 按 `LASER_HOME` → 冻结时 `%LOCALAPPDATA%\LaserWaypoint` → 源码时仓库根 的顺序解析 |
| `qt_compat` | Qt 绑定兼容层 | 交付用 **PySide6**（LGPL）；Linux 的 PySide6 wheel **没有 QtWebEngine**，所以退回系统 PyQt5（GPL，仅本地验证，`DEV_ONLY_BINDING` 会标记，冻结包里用 PyQt5 算自检 FAIL）。两个绑定只差三处：`Signal`/`pyqtSignal`、`Slot`/`pyqtSlot`、WebEngine 的 import 路径。**`QtWebEngineWidgets` 必须在 `QApplication` 之前导入**（Qt5 硬性要求），所以任何入口都先 `import laser_desktop.qt_compat`。**绝不能加 `--disable-gpu`**：Plotly 的 `Scatter3d` 靠 WebGL，加了之后图区只显示 "WebGL is not supported by your browser"（本机实测默认走 `Mesa Intel(R) Graphics`；无 GPU 的机器由 Chromium 自己退到软件渲染）。`configure_webengine_environment()` 只处理 sandbox（容器/提权下 setuid sandbox 会直接崩）与 Linux 的 `--no-zygote`（减少两个只有空壳的 zygote 子进程） |
| `plot_view` | 一个 `QWebEngineView` 里嵌 Plotly | 见下方“图视图”三条 |
| `job_bridge` | 把 `laser_web.jobs` 的后台任务接成 Qt 信号 | 见下方“任务桥” |
| `page_layout` | 三页共用的右栏布局、分割器、表格/图联动小工具 | 见下方“布局” |
| `licensing` | 启动闸门（找文件 + 说人话） | 见下方“许可证闸门” |

**图视图（`plot_view`）**

1. **离线壳页**：`plot_shell.html` + `plotly.min.js` + `qwebchannel.js` 一次性写到
   `cache_root()/plot/`，用 `file://` 加载——现场无外网，绝不引 CDN；
   `qrc://` 在 `file://` 页面上不可靠，所以 `qwebchannel.js` 是从 Qt 资源里拷出来落盘的。
2. **只加载一次**：换图走 `Plotly.react`（保留相机视角与缩放），重载 HTML 会白屏。
   `window.__baseSizes` 是换图时拍的**点尺寸快照**：`Plotly.restyle` 是就地改
   `gd.data[t].marker.size` 的，回头读 trace 会把上次的“选中 12 px”当成新基准，选过的点
   再也缩不回去。
3. **`shutdown()` 的顺序不能反**：先 `page.deleteLater()` + `flush_deferred_deletes()`，
   再 `setParent(None)` + `view.deleteLater()`。反了等于没修——`QWebEngineProfile` 是全局
   单例，关窗时还有活着的 `QWebEnginePage` 就会报
   “Release of profile requested but WebEnginePage still not deleted”，到 Windows 上就是
   “关窗报错 / 退出崩”。

**任务桥（`job_bridge`）**

- 工作线程里**只** `emit`（`_on_job_change`），绝不碰 QWidget/QTimer/QMessageBox；
  Qt 的 auto connection 发现“emit 线程 ≠ 接收对象线程”会自动排队，槽一定在 GUI 线程跑。
- GUI 线程收到通知不立刻刷，而是启动一个 **`FLUSH_MS` = 180 ms** 的单次定时器把一批变化
  合成一次；**终态（done/failed/cancelled）立即 flush**，取消要“点了就能看见”。
- 日志用**游标**取增量（`job.snapshot(cursor)`，绝对行号）：环形缓冲挤掉旧行时不会重复，
  但会插一行“已省略 N 行”——不能一声不响地少一段日志。
- 接管只限**同进程、同一个 `JobRegistry`**（重建页面时捡回在跑的任务）。另一个进程、
  哪怕同一个 `runs/` 目录，也接管不了（任务状态没落盘）。

**布局（`page_layout`）**

- `RightSplitter`：右栏**三段竖分割**（预览卡 / 3D 图 / 结果区），比例存
  `QSettings` 的 `right_splitter/<page>`；`BodySplitter`：左栏表单与右栏之间**两段横分割**，
  比例存 `body_splitter/<page>`，手柄 8 px（6 px 现场说“不知道这里能拖”）。
- 优先级：**主按钮完整 > 结果表 5 行 > 图 200 > 预览卡可压**。落地成常数就是
  `RESULT_TABLE_MIN_HEIGHT=200`（表头 + 5 行）、`PLOT_FLOOR_HEIGHT=200` /
  `PLOT_MIN_HEIGHT=260`（默认窗口守 260）、`PREVIEW_MIN_HEIGHT=100`；主操作按钮放在
  滚动区**之外**的固定行（`build_action_row`），窗口再矮也不会被切成半截。
- 用户拖过（`user_moved`）就不抢：`shrink_result_area` 与 `protect_plot` 都认这个标志。
  出结果时 `expand_result_area` 会主动把结果区撑到能看 8 行（先向图区借、图不低于 200 px）。
- 主窗口的**导航列**也是可拖的（在 `main_window`，不在 `page_layout`）：下限是“最长一项不被切字”
  的宽度、不设上限，宽度存 `QSettings` 的 `nav_width`；存过的值比当前下限还小就按下限算
  （换字体/DPI 后旧宽度可能切字）。

**许可证闸门（`licensing`）**

- **位置**：`__main__.main()` 里、建 `QApplication` **之前**、`import laser_web.core` **之前**。
  早于建窗口（源码运行时失败只往 stderr 打两行就退，不必付 Qt 启动成本）；早于读模型
  （授权不过就不该碰模型目录、不该建 `runs/`）。不通过退 **3**（与普通错误 1 区分）。
- **判定顺序**（越便宜越先）：找文件 → 公钥 → 读文件 → 验签 → 有效期 → 机器指纹。
  机器指纹要枚举物理网卡（Windows 上还走 PowerShell），所以放最后。
- **`check()` 永不抛异常**：任何底层异常都被翻译成 `ok=False` 的中文——现场看不懂堆栈。
- 失败时：冻结包弹一个对话框（`--windowed` 没有控制台，不弹就只剩“双击了一下什么都没发生”），
  源码模式只打 stderr（弹窗会挡住终端输出）。
- **`LASER_SKIP_LICENSE` 只在未冻结时生效**：冻结包里设了也会被忽略并写日志。
- 两个诊断开关（`--print-paths` / `--self-check`）**不过闸门**——它们是没证时唯一的排障手段，
  但都会把许可证状态报出来。

### 3.5.2 打包（`packaging/`）

| 文件 | 作用 |
| --- | --- |
| `desktop.spec` | PyInstaller 规格（**onedir**）：只读资产 → `_internal/assets`、QtWebEngine 运行时、瘦身、关键文件缺失就**让构建当场失败** |
| `build_windows.ps1` | 一键构建：Python 3.13 x64 → venv + 依赖 → `plotly.min.js` → 公钥检查 → 跑测试 → PyInstaller → `verify_dist.py` → ISCC 打安装包 |
| `setup.iss` | Inno Setup 6 安装包：`PrivilegesRequired=lowest`（免管理员）、装到 `{localappdata}\Programs`、固定 `AppId`、不写自启动、只收 x64 + Win10+、卸载时问要不要删运行记录 |
| `verify_dist.py` | 构建产物自检：**只看 `dist/`，不 import 仓库代码**（一旦 import 就变成“用同一份代码证明自己没错”） |

要点：

- **为什么 `--onedir` 不是 `--onefile`**：onefile 每次启动都要把 400+ MB 解到
  `%TEMP%\_MEIxxxx`（冷启动多 2–5 s），而且对 QtWebEngine 是**功能性**问题——
  `QtWebEngineProcess.exe` 要在启动那一刻按 `qt.conf` 的相对路径找到 `resources/` 与
  `Qt6*.dll`，解包目录一变就白屏。
- **公钥怎么进包**：`data/assets/license_public.pem` → `_internal/assets/license_public.pem`
  （`licensing.public_key()` 的两个候选位置之一）。没有这份文件**不算构建失败**（先出内测包、
  换一把钥匙都是正常需求），但 `verify_dist.py` 报 `[WARN]`、`build_windows.ps1` 醒目提示——
  包里没公钥，装到客户机上启动就报“程序缺少内置公钥”。**私钥绝不进包也不进仓库**：
  `verify_dist.py` 见到 PEM 里的 PRIVATE KEY 直接 `[FAIL]`。
- **`verify_dist.py` 查什么**：①必需文件（`QtWebEngineProcess.exe`、`resources/*.pak`、
  `icudtl.dat`、`plotly.min.js`、exe…，缺一个都可能是白屏）②私钥外泄 / 不该打进去的东西
  （`tests/`、`robot_sim/`）③体积（超出只 `[WARN]`）④真跑一次 `LaserCalibration.exe --self-check`。
- **构建机必须与目标机同 Python 版本（3.13）**：PyInstaller 不是交叉编译器，它复制的是
  **正在跑的那个解释器**连同 `.pyd`/`.dll` 与平台启动器。`build_windows.ps1` 硬性要求
  `3.13.*` + 64 位（目标机实测 3.13.17 x64），低了高了都可能打出一个“能装、一开就崩”的包。
- **体积预期**：解压后 **395–490 MB**、安装包 **155–200 MB**（`verify_dist.py` 的
  `EXPECTED_MIN_MB/MAX_MB`、`INSTALLER_MIN_MB/MAX_MB`）；`Qt6WebEngineCore.dll` 单独就
  203.5 MB，小于 180 MB 说明被裁过头了。

### 3.5.3 本地开发怎么跑

```bash
# 一把启动（venv 解释器 + PYTHONPATH + 跳过许可证 + 临时数据目录）
./scripts/run_local.sh              # 追加 --print-paths / --self-check 也行

# 不显示窗口的启动自检（逐项 [OK]/[FAIL]/[SKIP]，任一 FAIL 退 1）
PYTHONPATH=python QT_QPA_PLATFORM=offscreen .venv/bin/python -m laser_desktop --self-check

# 真 WebEngine 冒烟（真跑 8 点小案子、定位段、ISO 五点，截图到 /tmp/desktop_s*.png）
PYTHONPATH=python QT_QPA_PLATFORM=offscreen .venv/bin/python -m laser_desktop.smoke_offscreen

# 《操作说明书》那四张桌面版截图（真跑一遍再抓图，覆盖 docs/images/desktop/）
.venv/bin/python scripts/make_desktop_shots.py

# 三端数值一致（命令行 / 网页 core / 桌面 core）
.venv/bin/python scripts/parity_check.py --quick   # 8 点小域，秒级
.venv/bin/python scripts/parity_check.py           # 站点 50 点
```

上面最后两个脚本自己把 `python/` 插进 `sys.path`（只有命令行子进程需要显式传），
所以不必前置 `PYTHONPATH`；截图脚本自己会 `setdefault("QT_QPA_PLATFORM", "offscreen")`。

**`scripts/run_local.sh` 里为什么有 `LASER_SKIP_LICENSE=1`**：源码模式**也**校验许可证
（默认读 `data_root()/license.json`）。这是故意的——如果源码运行默认放行，就永远测不到
“没证的人打开会看到什么”，而那句话恰恰最需要打磨。代价是本地每次都要带跳过变量，
所以收进脚本；它只在**未冻结**时有效，打出来的 exe 不认。

**`--self-check` 查七项**：Qt 绑定 / `plotly.min.js` 可读 / 模型数与相对路径可解析 /
`data_root()` 可写 / **真起一个 `PlotView` 画出 8 个点再从壳页读回 `window.__state()`** /
物理网卡 / 许可证（**没有许可证不算 FAIL**，跳过；构建机上本来不该有绑定到构建机的授权）。
它不显示主窗口，所以 `QT_QPA_PLATFORM=offscreen` 下也能跑；**不加 `--disable-gpu`**
（那会把 WebGL 一起关掉，查不出真问题）。日志落在冻结时的 `data_root()/self-check.log`、
源码时的 `.cache/self-check.log`（不往仓库根扔日志，免得 `git status` 脏掉）。

**三端一致检查（`scripts/parity_check.py`）证明什么**：三个入口**共用** `laser_web.core`
（命令行只是多走一层 argparse + 子进程），所以它证明的是“**三个入口装配出同样的参数**”
——表单控件 → 参数字典 → argparse 名字空间这一路的映射、默认值来源、互斥项的取舍。它**不**证明
“三套独立实现算出同样结果”。脚本的 docstring 与每次输出都写着这句，别把它写成“三端互相印证”。

### 4.6 `licensing.__main__` —— 离线授权（签发 / 取证 / 校验）

授权是**离线签名文件**，不联网：签发方持 Ed25519 私钥，把"客户名 + 序列号 +
物理网卡指纹 + 有效期"签成 `.lic`；程序内嵌公钥，启动时验签 + 比对本机指纹。

```bash
# ① 客户机：取本机物理网卡指纹（原始 MAC 不用外发）
PYTHONPATH=python python3 -m licensing hwid

# ② 签发方：首次生成密钥（私钥 600，离线保管，绝不随程序分发）
PYTHONPATH=python python3 -m licensing issue --keygen private.pem public.pem

# ③ 签发方：按指纹签发
PYTHONPATH=python python3 -m licensing issue --key private.pem \
  --licensee "XX 公司" --serial R1-0001 --expires 2027-11-18 \
  --fingerprint <客户机指纹> --out R1-0001.lic

# ④ 现场：校验
PYTHONPATH=python python3 -m licensing verify R1-0001.lic --public-key public.pem
```

| 参数 | 含义 |
| --- | --- |
| `hwid` | 打印物理网卡与指纹（滤掉虚拟网卡、随机地址、可伪造的注册表覆盖值） |
| `issue --keygen PRIVATE PUBLIC` | 生成密钥对 |
| `issue --key ... --licensee --serial --fingerprint` | 签发；`--fingerprint` 可重复给多块网卡 |
| `--min-match N` | 命中几个指纹算同一台机器（默认 1，多网卡机器建议保持 1） |
| `--expires YYYY-MM-DD` | 有效期；不给 = 永久 |
| `--feature NAME` | 预留给按功能授权 |
| `verify --public-key` | 校验签名、有效期、机器绑定 |

实现要点（改代码前必读）：

- **只认物理网卡**：Windows 走 `Get-NetAdapter -Physical` 的 `PermanentAddress`（Win10 的
  随机硬件地址会让当前 MAC 变，固件地址不会）；Linux 要求 `/sys/class/net/<if>/device`
  存在。**绝不**读注册表 `NetworkAddress`（那是伪造 MAC 的地方）。
- **指纹不可逆**：授权文件里存 `sha256("laser-lic/v1:" + mac)` 的前 32 位，不存原始 MAC。
  前缀一变所有旧授权失效，因此有测试钉住它。
- **签名覆盖整个 payload 的规范 JSON**（键排序 + 紧凑分隔符），改客户名/有效期/指纹
  任一字段都会验签失败。
- **已知边界**：这是威慑与追溯，不是不可破解的 DRM——Python 程序可被改、MAC 可用驱动
  伪造；它挡的是"把安装包拷到另一台机器直接用"，并让授权可追。
- 依赖只在 `requirements-license.txt`（`cryptography`），核心算法不需要它。

### 5.1 生成一套 50 点的标定文件（scan + joints + GP）

`joints.txt` 由界面导出现在是**空格分隔、3 位小数**（与历史交付文件一致）。

### 5.2 现场报奇异，要重新出点

1. 记下控制器停机时的 6 个关节角，以及示教器上「已走到第几点」；
2. 用 `avoid_singularity`（或界面「奇异修复」页）传入这两样；
3. 看输出结论：
   - `窗口内各段都满足阈值，且整链无越界` → **模型复现不出该报警**，先核对点号/报警类型；
   - `报告段 GPxx->GPyy 越界` → 程序会给出修复方案（局部换姿态 或 整体平移/收缩）；
4. 修复后的 `scan50_repaired.json` 可直接交给 `export_gp`。

### 5.3 做 ISO 9283 定位精度测试

1. 生成 P1～P5（见 4.3 或界面「ISO 五点」页）；
2. 把 `iso5.json` 交给 `export_gp` 写成 GP（一般从 GP0001 起）；
3. 现场按 **MOVL** 依次走这 5 点，姿态保持一致，用跟踪仪测量。

### 5.4 缩小采样域但仍然要 50 点

改 `--point-min/--point-max` 即可，`--target-count 50` 会自动重新分配份数；
想知道会落到哪个网格，加 `--skip-ik` 先看一眼，或用界面的预览卡片。

## 6. 出错了怎么查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError: nicegui` | 用了系统 python | 改用 `.venv/bin/python` |
| `ModuleNotFoundError: excitation_trajectory` | 少了 `PYTHONPATH=python` | 命令前加 `PYTHONPATH=python` |
| 浏览器"无法连接" | 服务没在跑 | `ss -ltn \| grep 8765`，再 `tail -30 /tmp/laser_web.log` |
| `--host 只允许 127.0.0.1` | 想开局域网 | 有意不支持（无鉴权）；确有需要请先加鉴权 |
| `argument --euler: invalid choice: 'xyz-extrinsic'` | 定轴约定已移除 | 改成 `xyz-intrinsic`（见 7.2） |
| 服务启动即退出，日志有 traceback | 分支不对/依赖缺失 | 确认在 `feat/iso9283-p5` 或合入后的分支，`pip install -r requirements-web.txt` |
| 界面改参数后数字不更新 | 回调异常被吞 | 看 `/tmp/laser_web.log` 是否有 `TypeError`；报告给维护者 |
| `所有候选都不可行`（退出码 2） | 该域在该姿态下确实无解 | 缩小域、换参考姿态、放宽 `--j5-min`，或看报告里的逐候选原因 |
| `KeyError: 'Link&CoupleCoe'` | 拿仿真资产/扫描记录当模型 | 只能用控制器配置 JSON 或 URDF（界面下拉已过滤） |
| GP 导出报关节越界 | 关节角超出 ±360° 或非有限 | 检查上一步解算是否有异常点 |

服务端日志位置：`/tmp/laser_web.log`（后台启动时）。界面上的「日志」折叠区显示的是算法自己的输出。

## 7. 约定与术语

### 7.1 单位

| 量 | 单位 |
| --- | --- |
| 位置 / 杆长 / 采样域 | mm |
| 关节角、RPY | deg（命令行与界面输入） |
| GP 文件里的关节角 | deg |
| GP 文件里的笛卡尔姿态 | 默认 rad（`--cart-units` 可切 deg） |
| 条件数 | 无量纲 |

### 7.2 欧拉约定：只保留内旋

命令行与界面只提供三种，都是**内旋**（随体坐标系、顺序相乘）：

| 约定 | 旋转矩阵 | 说明 |
| --- | --- | --- |
| `xyz-intrinsic`（默认） | `Rx·Ry·Rz` | Nexus 控制器 `kXyzIntrinsic` 同款 |
| `zyx-intrinsic` | `Rz·Ry·Rx` | |
| `zyz-intrinsic` | `Rz·Ry·Rz` | 真欧拉角；`b = 0/±180°` 有万向锁，代码取 `A = 0` 的代表解 |

定轴 RPY（`Rz·Ry·Rx` 固定轴）**已从接口移除**：现场数据全是内旋读数，两套并存只会让
"这组 rpy 到底怎么读"变成猜。旧命令写 `--euler xyz-extrinsic` 会直接报错，不会静默按内旋处理。

### 7.3 ISO 9283 五点布点

| `--layout` | P2～P5 位置 | X/Y/Z 覆盖（边长 L） |
| --- | --- | --- |
| `vertices`（默认，ISO 标准） | 对角截面（`x = z`）的四个角 = 立方体四个顶点 | 全 `L` |
| `circle` | 同一截面的内切圆（半径 `L/2`） | `L` / `0.71L` / `L` |
| `center-square` | `z = -0.4h` 平面上边长 `0.8h` 的正方形四角 | `0.4L` / `0.4L` / **0** |

`center-square` 只为复现历史脚本布点；正式测试用 `vertices`（界面上固定就是它）。

**编号（`vertices` / `circle` 相同，ISO 9283）**：P1 = 立方体中心；P2 / P3 在小 X 小 Z
一侧（`(-h, +h, -h)` / `(-h, -h, -h)`），P4 / P5 在大 X 大 Z 一侧（`(+h, +h, +h)` /
`(+h, -h, +h)`），同侧两点只差 Y。以中心 `1000 0 600`、`L = 200` 为例：

| 点 | x | y | z |
| --- | --- | --- | --- |
| P1 | 1000 | 0 | 600 |
| P2 | 900 | 100 | 500 |
| P3 | 900 | -100 | 500 |
| P4 | 1100 | 100 | 700 |
| P5 | 1100 | -100 | 700 |

`center-square` 的编号是历史脚本的，**没有**按 ISO 9283 排序（只用于对照）。

### 7.4 MOVL 与 PTP

- **MOVL**（笛卡尔直线）：位置线性 + 姿态测地线插补，关节轨迹**不是**直线。现场 JOB 多用它。
- **PTP**（关节直线）：各轴按比例插补。

两者的奇异判定结论可能不同（同一批点实测：PTP 给段内 `|J5| 20.55°`，MOVL 给 `19.51°`）。
现场用 MOVL 就用 `--seg-mode cartesian`（界面默认已是）。

### 7.5 GP 文件的 14 字段

| 索引 | 含义 |
| --- | --- |
| `0..5` | 笛卡尔位姿（默认写 0；`--cartesian fk` 时由模型算出） |
| `6` | 标志位 |
| `7..12` | 六个关节角（deg） |
| `13` | 外部轴 |

### 7.6 关节角方向

导出的角度是**模型轴角**，与示教器读数一致，直接下发即可；**不要**因为控制器
`Direction` 里有 −1 就自动取反（驱动与协议层不使用 Direction）。

### 7.7 机型与文件

`data/configs` 下只有 URDF 与控制器配置 JSON 能当模型；`*_dh.json`（DH 覆盖）、
`*_scan.json`（扫描记录）、`robot_sim/*.json`（仿真资产）都缺 `Link&CoupleCoe`，不能直接用。
